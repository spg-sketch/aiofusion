---
name: Settings and onboarding visual relationship
description: Product decision for how initial onboarding relates to the permanent account-management experience.
---

Initial onboarding should remain a focused standalone process rather than appearing inside the permanent Account and Team Settings navigation. It should still share the same visual language: Inter body text, Alice headings, near-black reading text, pink selection states, and pink/navy icon treatments.

**Why:** Account type, company information, access choice, and optional payment form a required sequence. Showing ordinary settings navigation during this process suggests that users can safely skip around before setup is complete. The shared visual language preserves continuity without weakening the onboarding sequence.

**How to apply:** Keep project creation outside onboarding. After onboarding completes, route the user into the normal platform/account experience. Future onboarding steps should use the focused shell, while editable long-term controls belong in Account and Team Settings.

Project Hub is the approved button reference; subsequent Settings polish should be incremental and should not redesign Hub.

**Why:** The user is happy with Hub and requested consistency fixes rather than another foundation or layout redesign.

**How to apply:** Compare actual rendered controls first. Keep large Hub cards distinct from ordinary form actions, and isolate Settings changes from shared onboarding consumers.
