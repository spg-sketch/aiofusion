Brand and UI guidelines

01 / Executive summary

Converge the language, not the product surfaces.

The source already has a coherent character: warm editorial marketing, a focused pink and navy onboarding flow, and a cool, information-dense workspace. The audit finds token drift and casing drift, not a case for a new component library. Use one typographic hierarchy, role-based colour tokens and explicit context exceptions. Keep Project Hub exactly as approved.

Genuine drift

Type token mismatch

Source uses Alice for headings, while the global theme names DM Serif Display before Georgia. Proposed guidance approves Alice, Georgia, serif, so the token drift must be reconciled later.

Genuine drift

Colour roles split

Marketing uses dark teal #102B36 and cream. Product uses navy #0A1628 and cool neutrals. Both can remain when named by context, rather than treated as accidental duplicates.

Intentional density

Navigation and cards

Compact settings navigation, dense tables and the Hub's larger cards serve different tasks. Do not normalise these into a single density or card template.

Decision in one line

Adopt Alice plus Inter as the shared voice, pink as selection and action accent, navy or teal by surface, amber for the global keyboard focus cue, and documented exceptions for marketing, onboarding and Project Hub.

Spacing and shape

  • Use a 4px base rhythm: 8, 12, 16, 24, 32, 40, 56 and 72.
  • Reading cards use a 16px radius and 24 to 36px padding.
  • Ordinary product controls: 44px minimum height, 12px radius, 13px Inter bold.
  • Compact row actions: 36px minimum height, 10px radius, 12px text.
  • Inputs: 44px minimum height, 12px radius, visible label, helper and error copy.

Do not flatten density

The Hub's large create, archive and guidance cards are not ordinary form-button templates. Dense settings navigation and report tables are task-specific.

04 / Patterns

Rules that travel well.

These specimens are illustrative guidelines, not screenshots and not a component-library implementation.

Buttons and interactive states

Primary actionSecondaryOutlineText actionCompact row actionMarketing CTADisabled

Specimens only. Product buttons follow current .aio-button proportions. Marketing may use 8px radius and shorter CTAs.

  • Hover: modest brightness or border shift.
  • Active: one-pixel press or tone shift.
  • Focus-visible: 3px amber outline with 3px offset and dark offset ring. Pink means selection, not focus.
  • Disabled: reduced opacity and no pointer affordance.
  • Destructive actions use explicit red and confirmation copy.

Forms and subsections

  • Every control has a visible persistent label. Placeholder is an example, not the label.
  • Group related fields with clear headings. Keep errors adjacent, specific and announced where appropriate.
  • Use pink for selected choice and amber for focus. Use status colour with text or icon, not colour alone.
  • On mobile, stack fields before shrinking type and avoid horizontal scrolling for ordinary forms.

Project Set-Up exception

The pink-wash mini bar is approved only for field-grouping headings on the first Project Set-Up page, per .agents/memory/aio-fusion-subsection-headers.md. Do not extend it to reports, diagnostics, media research or planner headings.

Cards, tables and status

  • Give cards a clear title, supporting copy and one action hierarchy.
  • Use pale pink for selected state, pale teal for neutral context and cool slate for utility surfaces.
  • Dense tables may remain dense when scanning is primary. Provide a mobile scroll affordance.
  • Status badges use sentence case in prose. Uppercase is for compact eyebrows and labels.

Navigation terminology

  • Canonical label: My Account, not the source variant “My account”.
  • Use Project Hub, not Dashboard, for the approved workspace home.
  • Use Back to website and Back to platform in their respective contexts.
  • Use Project Set-Up, Media Research, Content Optimiser, Comms Planner and Reports.
  • Use UK spelling: optimise, organisation, personalised. Do not use em dashes.

Approved context exceptions

  • Marketing: teal #102B36, cream #FBF6EC, editorial Alice headings and public navigation.
  • Focused onboarding: standalone shell, pink selection, navy/teal icons and progress rail. No ordinary Settings navigation before setup completes.
  • Project Hub: existing palette, card scale, navigation and density are protected. Isolate changes from Hub consumers.
  • Settings: cool mint canvas, left navigation and ordinary form actions can follow the settings mapping without redesigning Hub.

Genuine drift to resolve first

  1. The global DM Serif token versus the approved Alice, Georgia, serif stack.
  2. Marketing teal/cream versus product navy/cool palette without role names.
  3. Button radius, casing and uppercase treatment.
  4. My Account versus My account.
  5. Orange global focus versus pink local focus.

Not drift to fix

  • Hub card scale and deliberate density.
  • Focused onboarding's standalone rail.
  • Settings navigation versus report tables.
  • Marketing editorial spacing.
  • Context-specific button hierarchy when labelled and measured.
06 / Rollout and acceptance

Ship the guardrails before the polish.

Roll out through small, reversible reviews. No app or source style changes are part of this documentation task.

1 / Protect

Freeze the Hub boundary

Record the Hub as approved. Audit selectors for indirect shared CSS impact before settings or token changes.

2 / Align

Resolve language tokens

Agree Alice plus Inter, role-based palette and terminology. Review marketing and product separately.

3 / Validate

Review by role and route

Render desktop and mobile states for Direct Client, Agency Partner and Master before accepting implementation.

Acceptance checklist

  • Current workspace home route / screenshot reviewed.
  • Desktop and mobile marketing navigation reviewed.
  • Desktop and mobile Hub reviewed unchanged.
  • Settings rendered for Direct Client, Agency Partner and Master.
  • Onboarding rendered for each permitted account role.
  • Project Set-Up keyboard path reaches every field and action.
  • Tools and reports checked at narrow viewport, including table overflow.
  • Keyboard focus visible on links, buttons, inputs, selects and dialogs.
  • Focus distinct from pink selection and hover.
  • Loading, disabled, error and destructive states checked.
  • Reduced-motion preference checked.
  • Terminology uses My Account, Project Hub and UK spelling.
  • No claim for routes or roles not actually rendered.
  • Indirect CSS blast radius checked before implementation merge.

Non-goals

  • No Project Hub redesign or palette replacement.
  • No component library or global CSS refactor.
  • No app/source style change, content rewrite, route rename, account operation or production change.
  • No invented official logo clearspace measurement.
  • No external fonts, images or dependencies in this HTML.
  • No claim that fixture screenshots prove authenticated behaviour.
  • No unsupported accessibility certification.

Logo use

The supplied colour logo is embedded as a PNG data URI. Keep artwork intact, do not redraw or crop it, and do not invent an official clearspace unit. Check contrast and background before choosing a logo variant.
