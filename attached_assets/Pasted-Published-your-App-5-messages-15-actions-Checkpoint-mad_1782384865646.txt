What happened:

The Archive was migrated from localStorage to the database — a one-time migration uploaded each browser's localStorage content to the DB
The DB was rebuilt/reset at some point, which wiped the archive_items table back to zero
The migration has a guard key (aio.store.migrated.v1 in localStorage) that prevents it re-running — so the re-upload never happened
Crucially: the content still exists in localStorage on whichever browsers it was originally created on — the migration never deletes from localStorage, it only copies to the server
How to restore it:

On each browser where content was originally created, open the browser's developer console (F12 → Console) and run this one line:

localStorage.removeItem('aio.store.migrated.v1')

Then refresh the page. The app will re-run the migration automatically and upload all the localStorage Archive and Planner content back to the database. It only needs to be done once per browser that has content on it.

Browsers/devices to check:

Wherever the SMG account content was created
Any other accounts where content is missing — same process, logged in as that account
Once done, the content will be back in the DB and visible from any browser/device (since it's now DB-backed, not localStorage-only).

This would be worth doing before the next DB maintenance so you don't lose it again. Once the content is back in the DB, it's properly backed up by the daily backup scripts and safe from browser-local data loss.
